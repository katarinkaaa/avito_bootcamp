# Final solution — Avito bot detection

## Что приложено

- `submission.csv` — готовый файл для отправки;
- `solution_final.ipynb` — полный код построения признаков, валидации и обучения;
- `metric.py` — реализация официальной метрики из задания;
- `requirements.txt` — версии основных зависимостей.

## Подход

Единица классификации — `cookie_id`. Все поведенческие признаки строятся только по событиям внутри строгого окна:

`window_start_ts <= event_ts < window_end_ts`.

Используются группы признаков:

- объём и разнообразие событий;
- количество и доли типов событий;
- объявления, категории, локации, продавцы и поисковые запросы;
- интервалы между событиями;
- burstiness и длительность активности;
- активные часы/минуты и профиль активности по часам;
- сессии;
- энтропии распределений;
- последовательности и переходы между типами событий;
- поисковое поведение;
- движение курсора;
- User-Agent и производные признаки;
- дубликаты событий;
- возраст cookie на начало окна.

### Модель

Финальная модель — ансамбль из трёх LightGBM с фиксированными seed. Порог в submission не выбирается: сохраняется непрерывный `score`, поскольку официальная система сама перебирает порог для `Precision при Recall >= 70%`.

### Валидация

Используется временная валидация: более поздние окна не попадают в обучение соответствующего holdout. Дополнительно проверяются несколько последовательных временных фолдов.

Baseline — Random Forest на `n_events` и `n_items`.
